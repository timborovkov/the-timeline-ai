# Documentation review

Read `AGENTS.md` and [documentation ownership](../../../docs/README.md). User scope and repository validation policy take precedence.

1. Establish the diff, baseline and requested scope. For a full documentation audit, inventory all maintained sources; for ordinary changes, identify affected owners and inbound links.
2. Verify changed claims against source, tests and dated external evidence. Code alone does not prove deployment, provider settings or legal approval.
3. Update each fact in one owner. Link elsewhere. Remove completed roadmap entries; retain unfinished substeps as explicit open work. Do not append local test counts, branch merges or routine review diaries.
4. Preserve unique external evidence, authority boundaries, migrations and rollback procedures. Historical evidence remains dated and separate from live instructions.
5. Edit generated documentation at its source. Treat distributed skills, email templates and executable examples as product artifacts with relevant validation.
6. Check formatting, relative links/anchors, deleted-path references and the final diff. Run application checks only when changed behavior requires them.
7. Report the actual scope, checks, unresolved external evidence and any limitations. Do not claim every document is current when only affected docs were reviewed.

A no-diff exploratory handoff needs no documentation churn. Commit, push, publish and deploy only within the user's authorized scope.
