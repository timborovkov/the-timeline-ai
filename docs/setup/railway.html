Railway deployment setup

SetupLast updated 2026-06-03

Project + environment provisioning for staging and production. For the full service architecture see docs/railway.html.

The repo ships ready-to-deploy railway.json files for web and worker. Provisioning the Railway project is a manual step.

1. Project + environments

  1. Create a new Railway project.
  2. In Settings → Environments, create staging and production.
  3. Settings → Git — connect the repo. Branch deploys:
    • main → production
    • staging → staging

2. Managed plugins

Add via + New → Database:

  • Postgres — Railway plugin. Copy DATABASE_URL from the plugin's Connect tab into the project's shared variables.
  • Redis — Railway plugin. Copy REDIS_URL likewise.

3. Custom services

Add via + New → Empty Service (or Deploy from Docker Image):

  • qdrant — image qdrant/qdrant:v1.12.4, attach a persistent volume at /qdrant/storage. Expose port 6333. Set QDRANT__SERVICE__API_KEY to a random value; copy to shared QDRANT_API_KEY. Set shared QDRANT_URL to the service's private URL.
  • rustfs — image rustfs/rustfs:latest, attach a persistent volume at /data. Set RUSTFS_ROOT_USER/RUSTFS_ROOT_PASSWORD. Map env to S3_ACCESS_KEY_ID/S3_SECRET_ACCESS_KEY in shared variables.

Run a one-shot minio/mc job to create buckets (same commands as rustfs-init in docker-compose.yml).

4. App services

Add web, worker, and extract services pointing at this repo. Use apps/web/railway.json, apps/worker/railway.json, and apps/worker/railway.extract.json respectively. All three use Railpack build commands that install the pnpm workspace and build the packages they run. App services also run the shared DB migrator in preDeployCommand; the advisory lock makes overlapping deploys safe. Portable app Dockerfiles live in docker/; do not add a root Dockerfile for these services.

The extract service is the credential-thin document-extract consumer (ADR 0013). Set WORKER_MODE=document-extract, DAYTONA_API_KEY, DAYTONA_SNAPSHOT=timeline-document-extract, OPENROUTER_API_KEY, DATABASE_URL, REDIS_URL, and S3 document-bucket variables. Do not set SECRETS_ENCRYPTION_KEY, Auth secrets, or Telegram/Slack/integration OAuth tokens on extract. On the main worker, set DOCUMENT_EXTRACT_ENABLED=false so only extract consumes that queue. Create the Daytona snapshot once with pnpm --filter @timeline/worker create-document-extract-snapshot.

5. Shared variables

In Settings → Variables, set everything from .env.example that isn't a local-only default. Mark provider tokens and secrets (OpenRouter, Telegram, Slack, Postmark, Sentry, and native integration OAuth client secrets such as GitHub, Linear, and Monday.com) as secret. PostHog's public project key and host are not secrets, but keep them environment-specific.

TELEGRAM_BOT_TOKEN must be available to both app services. The web service owns webhook authentication and keeps the initial typing heartbeat active until the worker claims the durable conversation-agent job. The worker then owns the four-second typing refresh and final Telegram reply. Slack delivery reconstructs its worker adapter from encrypted installed-workspace tokens using SECRETS_ENCRYPTION_KEY, so do not add a separate Slack bot token variable.

Keep NODE_ENV as production for both Railway environments. Use the Railway environment name and SENTRY_ENVIRONMENT for labels like staging; the app rejects NODE_ENV=staging.

Set AUTH_URL to the primary public origin, such as https://thetimeline.cc. The web proxy redirects alternate hosts, including www and Railway's default *.up.railway.app host, back to this origin before Auth.js runs.

For production abuse controls, also set TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, and SUPPORT_EMAIL. Turnstile is only rendered on anonymous public forms: email/password registration and /help/support. OAuth sign-up and signed-in app forms do not show CAPTCHA; they use rate limits, permission checks, and product quotas instead.

For product analytics, set NEXT_PUBLIC_POSTHOG_KEY and NEXT_PUBLIC_POSTHOG_HOST=https://eu.i.posthog.com. For error monitoring, set SENTRY_DSN, NEXT_PUBLIC_SENTRY_DSN, NEXT_PUBLIC_SENTRY_TRACES_SAMPLE_RATE, NEXT_PUBLIC_SENTRY_PROFILES_SAMPLE_RATE, SENTRY_ENVIRONMENT, SENTRY_TRACES_SAMPLE_RATE, SENTRY_PROFILES_SAMPLE_RATE, and optional source-map upload variables SENTRY_AUTH_TOKEN, SENTRY_ORG, SENTRY_PROJECT, and SENTRY_RELEASE. Source-map variables must be available during the Railway build phase for both the Next.js upload and worker sentry-cli upload.

For LLM observability, set LANGSMITH_TRACING=true, LANGSMITH_API_KEY, and LANGSMITH_PROJECT=timeline-production. Keep LANGSMITH_ENDPOINT=https://api.smith.langchain.com unless the workspace uses another LangSmith region, and set LANGSMITH_WORKSPACE_ID when using an org-scoped API key. Rich LangSmith traces include private prompt and output content from timeline events, documents, meetings, and integrations, so treat LangSmith access as sensitive operational access. Set LANGSMITH_TRACING_SAMPLING_RATE to a value between 0 and 1 to cap trace volume. Raw media/audio bytes are redacted from traces, and embeddings are not sent to LangSmith by default.

6. Healthchecks

Already configured in apps/web/railway.json → /api/health. Railway will restart the service on failure.

7. Job reconciler (optional cron)

Set CRON_SECRET in shared variables to enable POST /api/cron/reconcile. The endpoint re-enqueues stuck transcribe / extract / embed jobs for raw events idle past 15 minutes, and is idempotent because workers are deterministic on raw_events and Qdrant point ids. Run it from Railway's scheduler (or any cron service) every few minutes: 

curl -fsS -H "Authorization: Bearer $CRON_SECRET" \
  https://thetimeline.cc/api/cron/reconcile

Leave CRON_SECRET unset to disable the endpoint (returns 503). The handler also accepts GET for cron services that don't support POST bodies.

Dead-letter behavior. Each (row, stage) is re-enqueued at most 3 times. After that the reconciler stamps source_metadata.reconcile_giveup_<stage> with the giveup timestamp and skips the row on subsequent runs. The response payload includes a deadLettered count for dashboards. To retry a dead-lettered row manually, clear the giveup key from source_metadata: 

UPDATE raw_events
SET source_metadata = source_metadata
  - 'reconcile_giveup_transcribe'
  - 'reconcile_attempts_transcribe'
WHERE id = '<uuid>';
