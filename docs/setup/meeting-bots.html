Meeting bot setup

SetupLast updated 2026-05-25

Paste a Google Meet, Microsoft Teams, or Zoom link into /app/meetings. A silent Recall.ai bot joins, streams the transcript back via webhook, and every utterance lands on the timeline.

Phase 10 adds meetings as a first-class source alongside Telegram, email, web capture, and documents. The bot joins silently (it appears as a participant but does not speak or stream video). Each finalised utterance is written as a raw_events row with source='meeting' AND as a meeting_transcript_chunks row so the existing extract / embed / visibility pipeline lights up unchanged while the meeting detail page renders a structured speaker-by-speaker transcript.

Why Recall.ai (and what else works)

Recall.ai is the default provider — handles all three platforms (Meet / Teams / Zoom) with one API, ships a hosted bot fleet so we don't run audio infrastructure. Per-minute pricing applies; check current rates at recall.ai.

The provider lives behind a MeetingBotProvider interface (packages/shared/src/meeting-bots/). Swapping to one of the alternatives below is a single-file change — webhook routes, scope helpers, and the worker all stay the same.

  • Attendee.dev — self-hosted, cheaper per minute, more ops overhead. Use if Recall.ai cost becomes the bottleneck.
  • Meeting BaaS — similar to Recall, alternative pricing.
  • Native APIs (Google Meet Media API, Teams Real-Time Media) — lowest cost but each platform is a separate integration.

1. Account + API key

  1. Sign up at recall.ai.
  2. Create an API key from the Recall dashboard.
  3. Copy the Region URL (default us-west-2).
RECALL_API_KEY=...
RECALL_BASE_URL=https://us-west-2.recall.ai/api/v1

2. Webhook endpoints

Two webhooks. Status events are Svix-signed; transcript events are unsigned and validated by bot id lookup.

  1. Status webhook (Svix-signed). In the Recall dashboard, configure the webhook URL to: 
    https://<your-app-domain>/api/webhooks/recall/status
    Copy the Svix signing secret it generates. Set: 
    RECALL_STATUS_WEBHOOK_SECRET=whsec_...
  2. Transcript webhook. We pass this URL to Recall on every POST /bot call. By default it is derived from AUTH_URL (your app's public origin, already required by Auth.js) plus the fixed route path, so most installs need no additional config — the bot posts to ${AUTH_URL}/api/webhooks/recall/transcript. Set RECALL_TRANSCRIPT_WEBHOOK_URL only when transcripts should hit a different origin (proxy, tunnel for local dev, separate webhook ingress): 
    # Optional — defaults to AUTH_URL + /api/webhooks/recall/transcript
RECALL_TRANSCRIPT_WEBHOOK_URL=https://<your-app-domain>/api/webhooks/recall/transcript
    This endpoint is NOT Svix-signed — Recall does not sign realtime transcript events. Authentication relies on:
    • Bot id lookup — bots are issued by Recall after our authenticated joinMeeting call. A forged bot id can't match any meeting in our database.
    • Zod validation — malformed payloads are rejected.
    • Rate limit — 600 transcript events/minute per bot.

3. Bot display name (optional)

The bot still appears as a participant in silent mode — every meeting platform surfaces it in the participant list. Set a recognisable name so attendees know what it is: 

RECALL_BOT_DISPLAY_NAME=Timeline

Cost guardrails

team_meeting_settings.meeting_minutes_cap sets a per-team monthly cap (default 600 minutes). Set to 0 to disable bots for a team. Set to null for unlimited. Admins can toggle meeting_minutes_admin_override to ignore the cap during a launch / incident window.

Each finalised meeting writes a row to meeting_usage. The scheduleMeetingBotAction server action sums the current month's minutes before allowing a new bot to join.

Privacy and consent

team_meeting_settings.require_host_consent (default true) forces the user scheduling the bot to tick a consent box confirming participants will be told the bot is recording. The timestamp is stored on meetings.metadata.consent_given_at.

We do not retain the raw audio. The Recall recording artifact remains on Recall's storage under their default retention; we explicitly do not copy it to our S3. Transcript text + summary land on the timeline; audio does not.

Local development

Use ngrok or Cloudflare Tunnel to expose localhost:3000 to Recall:

ngrok http 3000
# point RECALL_TRANSCRIPT_WEBHOOK_URL at the public ngrok URL

The Recall dashboard supports a test bot you can attach to a Meet you control. The transcript webhook fires within a few seconds of each utterance.

Troubleshooting

  • Meeting stuck in joining — check Recall dashboard for the bot's status. Recall surfaces fatal errors (e.g. host blocked the join) on the bot detail page.
  • No transcript chunks landing — verify RECALL_TRANSCRIPT_WEBHOOK_URL is publicly reachable. Check the web app logs for web:api:recall:transcript entries.
  • 401 on status webhook — Svix signature mismatch. Re-copy the signing secret from the Recall dashboard into RECALL_STATUS_WEBHOOK_SECRET.
