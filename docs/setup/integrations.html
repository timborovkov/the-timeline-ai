Integrations & custom MCPs

SetupLast updated 2026-05-25

Connect Google Drive, Linear, and GitHub from /app/team/integrations, or plug arbitrary custom MCP servers in at /app/team/mcp-servers. Every synced external event lands on the timeline as source='integration' and becomes searchable and citable by the agent.

Encryption key (required first)

All integration auth (OAuth refresh + access tokens, bearer tokens, custom-header values, basic-auth credentials, MCP dynamic-client secrets) is encrypted at rest with AES-256-GCM in packages/shared/src/crypto/secrets.ts. Generate a 32-byte key and set SECRETS_ENCRYPTION_KEY in your environment: 

node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

The first encryptSecret() call throws with a clear message if the key is missing or the wrong length, so worker boot fails fast instead of writing plaintext.

Google Drive

  1. Create an OAuth 2.0 client at console.cloud.google.com (type: Web application).
  2. Add the redirect URI: https://thetimeline.cc/api/integrations/google_drive/callback.
  3. Enable the Google Drive API for the project.
  4. Set: 
    GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
# REQUIRED before accepting Drive webhooks. 32+ bytes of randomness.
GOOGLE_DRIVE_WEBHOOK_SECRET=...
  5. Restart the web + worker services. The card on /app/team/integrations turns from Not configured to Connect.
  6. (Optional) Register a Drive push-notification channel for incremental sync. The channel token must be <integration_id>.<HMAC-SHA256(GOOGLE_DRIVE_WEBHOOK_SECRET, integration_id)>; route hits /api/webhooks/google-drive. The handler refuses inbound notifications when the secret is unset, and rejects bad signatures.

Linear

  1. Create an OAuth application at linear.app/settings/api/applications.
  2. Redirect URI: https://thetimeline.cc/api/integrations/linear/callback.
  3. Set: 
    LINEAR_CLIENT_ID=...
LINEAR_CLIENT_SECRET=...
LINEAR_WEBHOOK_SECRET=...
  4. In Linear Settings → API → Webhooks, point the webhook at https://thetimeline.cc/api/webhooks/linear with the secret above.

GitHub

  1. Create an OAuth App (or a GitHub App with OAuth) at github.com/settings/developers.
  2. Callback URL: https://thetimeline.cc/api/integrations/github/callback.
  3. Set: 
    GITHUB_APP_CLIENT_ID=...
GITHUB_APP_CLIENT_SECRET=...
GITHUB_WEBHOOK_SECRET=...
  4. Add a webhook on each repo / org pointing at https://thetimeline.cc/api/webhooks/github. Content type application/json; secret matches the env var; subscribe to Pull requests and Issues.

Custom MCP servers (inbound)

Bring tools from any MCP-compatible server into the agent's toolset. Visit /app/team/mcp-servers (team catalog — admins only) or /app/me/mcp-servers (personal overlay — visible only to you, any member can add). Pick an auth mode:

  • None — public MCP servers with no auth.
  • Bearer token — API keys / personal access tokens.
  • Custom header — arbitrary header name + value.
  • OAuth — server speaks the MCP OAuth dance; state JWT-equivalent is HS256-signed with AUTH_SECRET (no extra env var). Access tokens auto-refresh on expiry; if refresh fails the chat inline-renders a Reconnect button.

Discovered tools appear under the server with a Test call button (admin for team servers, owner for personal). Tools are namespaced as mcp__<serverIdCompact>__<toolName> and merged into the agent's toolset on every /api/chat request. Outputs are fenced through fenceExternalContent so the agent treats them as untrusted data per Rule 8 of the system prompt. A background mcp-health worker pings every enabled server on a 5-minute schedule and surfaces last_connected_at / last_error in the UI.

Timeline as an MCP server (outbound)

Expose this Timeline as an MCP server so external agents (Claude Desktop, Cursor, web-based agents, etc.) can query its events, entities, and documents. Admins mint bearer keys at /app/team/mcp-share:

  1. Go to /app/team/mcp-share and copy the MCP endpoint URL shown there.
  2. Click New key, give it a label (e.g. "Claude Desktop — personal mac"), and copy the one-time plaintext.
  3. In the consuming agent, add an MCP server with:
    • URL: https://thetimeline.cc/api/mcp/server
    • Header: Authorization: Bearer tla_...

The server speaks MCP protocol 2024-11-05 over streamable HTTP. Methods: initialize, tools/list, tools/call, resources/list, resources/read, prompts/list, prompts/get. Tools exposed:

  • timeline.search_events — semantic search across raw events
  • timeline.get_event / timeline.list_events — fetch + paginate
  • timeline.get_entity — lookup person / company / project / topic
  • timeline.search_documents — semantic search across the team document drive

Isolation: bearer keys are team-scoped, not per-user. The handler runs all queries with a pseudo-zero-UUID actor so events with visibility=private or specific_users stay invisible to outbound clients — only visibility=team events flow out. Keys are stored as SHA-256 hashes (plaintext shown once at creation). Revoke from the same page; revocation is immediate.

Wildcard CORS is set so browser-based agents work; Authorization-header auth means cookies cannot authenticate the cross-origin call. Per-IP rate limit 600/min.

How sync runs

A BullMQ repeatable enqueues an integration-sync tick every 5 minutes. The worker fans out to every enabled integration and runs incrementalSync() on each provider, using the per-resource cursor in integration_sync_state. Webhook hits enqueue an extra one-shot incremental for the same integration.

Manual full backfill from the CLI:

pnpm --filter @timeline/worker integration-resync -- --team=<uuid> --from-zero

Audit log

Every connect, sync start, sync finish, sync error, and replay writes a row in integration_audit_log. /app/team/integrations/audit renders the most recent 200 rows. The agent's list_integrations tool also surfaces connected providers + their last_synced_at.

Troubleshooting

Webhook returns bad_signature
Check the secret env var matches what the provider's webhook UI shows. The signing algorithm is HMAC-SHA256 over the raw body — make sure the provider hasn't re-serialised the JSON in transit.
Connect button stays disabled
The provider's OAuth client env pair is missing or empty. Set both CLIENT_ID and CLIENT_SECRET and restart.
Sync runs but no timeline events
The agent's dedup_key partial unique index makes replay a no-op. Use --from-zero on the resync script to wipe the cursor and re-walk from provider epoch.
