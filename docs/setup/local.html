Local development

SetupLast updated 2026-07-18

Bring up the full Timeline stack on your machine with Docker Compose for infra and pnpm dev for app + worker hot reload.

The full local stack runs in Docker Compose; the app and workers run on the host with hot reload.

Prerequisites

  • Node 24+ (LTS — see .nvmrc)
  • pnpm 11.8+
  • Docker Desktop (or compatible)

First-time setup

cp .env.example .env
# Next.js dev server reads env from the app dir, so symlink:
ln -sf ../../.env apps/web/.env

Fill in at minimum:

  • AUTH_SECRET — openssl rand -base64 32
  • SECRETS_ENCRYPTION_KEY — 32-byte base64 key required as soon as you connect any Phase 11 integration or custom MCP server. Generate with openssl rand -base64 32. See integrations setup.

The rest of the defaults already match docker-compose.yml.

TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, and SUPPORT_EMAIL can stay empty locally. Empty Turnstile secrets fail open outside production so developers can create email/password accounts without a Cloudflare widget.

Start infra:

docker compose up -d
docker compose ps           # all services should be "healthy"

This brings up Postgres (5432), Redis (6379), Qdrant (6333/6334), RustFS (9000 S3 API, 9001 console). The rustfs-init container runs once to create the required buckets, enable versioning, and allow direct browser document uploads from any local localhost or 127.0.0.1 port, including isolated worktree and E2E servers.

Install deps, run migrations, and optionally seed demo data:

pnpm install
pnpm db:generate            # only if you changed schema
pnpm db:migrate
pnpm dev:seed               # optional demo team, users, events, objects, integrations, reconciliation provenance

pnpm dev:seed only runs against local database hosts unless you set an explicit override, and it requires AUTH_SECRET, DATABASE_URL, and SECRETS_ENCRYPTION_KEY. It creates owner@timeline.dev and member@timeline.dev with password timeline-dev. The seeded GitHub and Linear credentials are fake, encrypted, and disabled for sync. Daily digest email is disabled for the demo users so the worker can run without outbound email configuration. Seeded canonical objects leave legacy source_event_id empty and expose demo provenance through reconciliation evidence, associations, and applied outputs.

Run the app:

pnpm dev

Open http://localhost:3000.

Phase 1 walkthrough

  1. Sign up as user A — you land on /app with a default team.
  2. Post a text note — appears in the timeline.
  3. Go to Team settings → invite user B by email. If POSTMARK_SERVER_TOKEN and TRANSACTIONAL_EMAIL_FROM are set, user B receives the invite email. Otherwise the invite is still created with a visible send error and copyable fallback URL.
  4. Open the invite URL in an incognito window, sign up as user B → user B is added to the team. If user B is already signed in with an account whose email matches the invite, the invite also appears in the team switcher modal with accept and decline actions; email verification is encouraged but not required for invite acceptance.
  5. Post a note as user B; both users see it.
  6. As user A, open the team switcher, create a second team, then switch teams → empty timeline (isolation works).

Phase 3 walkthrough (voice notes)

  1. docker compose up -d — verify rustfs, redis, and postgres are healthy. The rustfs-init container should report RustFS buckets ready.
  2. pnpm dev runs both Next.js and the BullMQ worker (apps/worker) in watch mode.
  3. Open /app, click Record, speak for a few seconds, click Stop, then press the form's Post button (the single submit handles both text and voice; add a note alongside the clip if you want). A new event lands with an audio player, your typed note when present, and a "Transcribing…" placeholder for the pending transcript.
  4. With OPENROUTER_API_KEY set in .env, the transcript joins the note and replaces the placeholder within ~10s (page refresh required for now — no realtime pushdown yet). Without the key, the audio is still recorded and playable; the worker retries the transcribe job with exponential backoff until the key is provided and the worker restarts.
  5. Telegram voice memos: send a voice note to the bot in a /link-ed DM (or bound group). The same flow runs: download → RustFS → enqueue → transcribe → backfill content_text.
  6. Re-deliver the same Telegram webhook to confirm idempotency: the row's tg_update_id is unique, so the second insert is a no-op and no second transcribe job is enqueued.

pnpm validate                         # format, typecheck, lint, knip
pnpm test                             # unit + integration tests (package suites run sequentially)
pnpm test:eval                        # fast deterministic agent/dashboard/retrieval/summary/proposal evals

                                      # opt-in live LLM askAgent durable-state + provider/document retrieval eval
SUGGESTIONS_LIVE_ENV_FILE=/path/.env pnpm test:suggestions-eval:live
                                      # opt-in live LLM suggestion extraction/projection eval
pnpm test:reconciliation-eval         # deterministic reconciliation domain/eval checks + sampling CLI gate
RECONCILIATION_LIVE_ENV_FILE=/path/.env pnpm test:reconciliation-eval:live
                                      # opt-in live LLM planner + judge matrix
# optional: RECONCILIATION_LIVE_ARTIFACT_DIR=/tmp/eval-run writes one exact output dir
# optional: RECONCILIATION_LIVE_ARTIFACT_ROOT_DIR=eval-runs/reconciliation writes timestamped runs
# optional: RECONCILIATION_LIVE_CALL_TIMEOUT_MS=90000 tunes each live planner/judge call
# optional: RECONCILIATION_LIVE_MAX_ATTEMPTS=3 retries transient planner,
# judge, and judge-consistency failures
pnpm test:e2e-env                     # deterministic E2E env/port contract check
pnpm test:dist-imports                # build db/shared and import compiled runtime modules with Node
pnpm --filter @timeline/worker reconciliation-evidence -- --team=<uuid> --mode=audit
pnpm --filter @timeline/worker reconciliation-evidence -- --team=<uuid> --mode=audit --fail-on-release-gate
# optional: repeat --allow-degraded-source=<event_source> for known historical degraded replay rows
pnpm --filter @timeline/worker reconciliation-evidence -- --team=<uuid> --mode=backfill --dry-run --page-size=500
TIMELINE_ENV_FILE=/path/to/.env pnpm --filter @timeline/worker reconciliation-legacy-provenance -- --team=<uuid> --fail-on-legacy
TIMELINE_ENV_FILE=/path/to/.env pnpm --filter @timeline/worker reconciliation-production-sampling -- --input=/tmp/eval-run --out=/tmp/reconciliation-production-sampling.json --team=<uuid> --run-kind=closed_beta --fail-on-failures
# production sampling accepts repeated --input paths; --run-kind defaults to manual
# and may be manual, closed_beta, or post_deploy. Use --fail-on-failures for
# release gates that should stop on any failed sample. Repeat
# --confirm-fixture=<caseName>:<packetFingerprint> for reviewed failed samples
# that should become deterministic fixtures.
# pnpm dev also starts the reconciliation queue consumer for enqueued
# evidence_audit/evidence_backfill/scope_reconcile jobs. Admins can enqueue
# source-scoped audit/backfill and repair scoped team/object/cluster evidence
# plus approval projections from /app/team/reconciliation. Completed
# audit/backfill jobs persist reconciliation_runs metrics, including
# release-gate failures for audit runs.
pnpm check:web-bundle                 # scan built Next server chunks after a web build
pnpm e2e                              # Playwright core journeys; requires compose infra + migrations
pnpm e2e:prod-smoke                   # build + standalone-server smoke; requires compose infra + migrations
pnpm e2e:setup / pnpm e2e:cleanup     # seed/remove deterministic e2e users and team
pnpm dev:seed                         # seed local demo data with disabled fake integrations and reconciliation provenance
pnpm lint && pnpm typecheck           # quick static checks
pnpm knip                             # dead code / unused deps
pnpm format                           # prettier write
pnpm db:studio                        # drizzle studio at localhost:4983
docker compose logs -f postgres       # tail a service
docker compose down -v                # nuke local data

Local E2E commands auto-detect published ports from a running timeline-e2e-* isolated Docker stack before falling back to the standard localhost:5432, 6379, 9000, and 6333 ports. Set DATABASE_URL, REDIS_URL, S3_ENDPOINT, or QDRANT_URL explicitly to override this, or set E2E_USE_DOCKER_PORTS=0 to force the fallback defaults.

GitHub PR CI intentionally skips pnpm build and pnpm check:web-bundle. The required CI proof is formatting, TypeScript compilation, linting, Knip, deterministic reconciliation evals, and the compiled-package import smoke check. Run broader relevant test commands separately, including pnpm test:eval for agent, retrieval, summary, dashboard chat, or proposal changes, and run the production build and bundle hygiene checks manually when changing deploy output, bundling, or server/client import boundaries.

Resetting local data

To recreate the Docker volumes:

docker compose down -v && docker compose up -d
pnpm db:migrate

Troubleshooting

  • DATABASE_URL is required — .env not picked up. Confirm the file exists at the repo root and Next.js was restarted.
  • Migrations stuck — docker compose logs postgres; ensure container is healthy.
  • Port already in use — another local Postgres/Redis on the same port. Stop it, or edit docker-compose.yml to remap.
