Sentry setup

SetupLast updated 2026-05-22

Optional locally. Strongly recommended before production.

Hook the web and worker services into Sentry for error tracking. The integration is wired in code and stays disabled when DSNs are blank.

1. Project

  1. Sign up at https://sentry.io.
  2. Create a project — platform next-js for web, node-express for worker.
  3. Copy the DSN.

Set in .env:

SENTRY_DSN=https://...@o0.ingest.sentry.io/0
NEXT_PUBLIC_SENTRY_DSN=https://...@o0.ingest.sentry.io/0
NEXT_PUBLIC_SENTRY_TRACES_SAMPLE_RATE=0
NEXT_PUBLIC_SENTRY_PROFILES_SAMPLE_RATE=0
SENTRY_ENVIRONMENT=development
SENTRY_TRACES_SAMPLE_RATE=0
SENTRY_PROFILES_SAMPLE_RATE=0

2. Wiring

The web service initializes Sentry from the Next.js instrumentation files and routes browser events through /sentry-tunnel. The worker initializes @sentry/node on startup, captures fatal startup/shutdown errors, and flushes before exit.

Keep sendDefaultPii disabled. Do not attach cookies, auth headers, prompts, transcripts, filenames, uploaded content, or raw document text to Sentry events. The scrubber removes request cookies and auth headers before send.

3. Source maps

Set these only in CI/deploy environments that should upload source maps:

SENTRY_AUTH_TOKEN=
SENTRY_ORG=
SENTRY_PROJECT=
