# Boards are curated work surfaces

Boards are curated work surfaces with explicit membership, not merely saved
filters over every workspace object. Filters and templates help teammates find
eligible objects, but a board item exists only when a workspace object is
intentionally added to that board or an approval-backed suggestion is accepted.
Board-local state such as lane, position, responsible person, due date,
priority, next step, and board notes belongs to the board item, while object
memory remains the canonical team understanding of the underlying workspace
object. This makes boards usable for CRM pipelines, task boards, product
catalogs, and other team workflows without letting broad object types flood
every board.

Add item can attach any workspace object type. The existing-object picker
prefers the board's recommended types so a sales pipeline is not buried under
recent tasks, and type filters plus search look up people, companies, and other
objects beyond that first window.
